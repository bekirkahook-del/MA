- **Every production deploy costs 15 Netlify credits (plan: 1,000/month).**
- **ALWAYS ASK BEKIR BEFORE ANY DEPLOY (Bekir, Nov 20, 2026, in caps).** Never push site changes to `main` or run `tools/deploy.sh` until he says "deploy" in that conversation. After queuing work, end by asking: "Want me to deploy? (~15 credits)"
- **DEPLOY QUEUE (Bekir, Nov 20, 2026): site changes never go straight to `main`.** Commit and push them to the `staging` branch (Netlify ignores it, free). They wait there until Bekir says "deploy"; then run `sh tools/deploy.sh` (merges staging into main = one deploy). `sh tools/queue.sh` lists what's waiting. When you finish a change, tell Bekir it's queued, not live.
  - Exception: content that never triggers a build (`social/`, `data/wire.json`, `guides/_src/`, `supabase/`, `tests/`, `*.md`) can still go straight to `main`.
- `netlify.toml` `ignore` skips deploys when a push only touches `data/wire.json`, `social/`, `guides/_src/`, `supabase/` or `*.md`.
- Always `git pull --rebase` before `git push` (for staging: `git pull --rebase origin staging`). The push prints a "repository moved" notice; it's harmless.
- Static site: `index.html` + `js/app.js` (big classic script; globals `S`, `isPro()`, `questEvt()`), `js/rewards.js` (Pro page, billing sync), `js/grow.js` (sign-up nudges + funnel events), `js/admin.js` (owner stats page, `#stats`).
- Guides are generated by `guides/_src/*.py` (`extra.py`, `seo.py`, `og.js`).
  - Site search (Ctrl K, `js/search.js`) searches guides via `js/guideidx.js`. After adding or regenerating guides run `python3 tools/guideidx.py`.
  - `guides/_src/build.py` currently fails (its base template changed), so built guide pages are edited in place. After any regeneration run `python3 guides/_src/expand.py` (extra sections on 18 short guides) and `python3 guides/_src/descfix.py` (meta descriptions ≤160 chars). Both are safe to rerun.
- Market search: `js/companies.js` (5,800+ company list) loads after the page's load event (`coLoad()` in app.js). `js/marketplus.js` adds company logos (via `netlify/functions/logo.mjs`, our domain, CDN 30 days, falls back to the letter avatar), the price card (live price, 1M–1Y chart, 52-wk range, volatility, drawdown) and "Look up XYZ" for tickers not in the list; `js/montecarlo.js` adds the 1-year Monte Carlo. Both use `netlify/functions/history.mjs` (Yahoo, CDN-cached 30 min) via `window.maHist`. New listings: add a row to `js/companies.js` and, if it should be on the tape, to `CORE` in `netlify/functions/ticker.mjs` + `TINFO` in app.js (Anthropic = ANT was added Nov 19, 2026).

## Backend
- Supabase table `docs` (col, id, uid, data). Users can't write `billing` or `ai_usage`; `views/_pro` is the server-written list of Pro members.
- Netlify functions in `netlify/functions/`. Shared helpers in `_lib/common.mjs`: `tierOf()`, `AI_LIMITS`, `rebuildProList()`, `isOwner()`.
- Pay tiers are decided on the server from the billing doc: free (3 AI uses/day), trial (3 days, once per account, 20/day), season (40/day), pro (100/day). Earned rank-up Pro days = trial level. `grant.mjs` = owner gives Pro.
- Stripe is live: webhook `stripe-webhook.mjs` listens to checkout.session.completed + customer.subscription.created/updated/deleted. Secrets live only in Netlify env vars; never ask for, paste or print them.
